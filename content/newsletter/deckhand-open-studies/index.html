Main Street · How we use AI

Deckhand studies now published with its data, code and prompt

The Deckhand Chronicles is AceEngineer's newsletter. We help build AI into everyday engineering work.

What we did

AI models and prompts will keep changing. We want our articles and analysis to stay traceable through those changes. So every Deckhand study is published with its data set, its code at one fixed version, a reusable prompt and the values to match. Our Deckhand team of AI assistants runs each study on public data, in code we publish.

Why it matters

AI work has its own form of a classic programmer complaint: "I ran what you ran but I did not get the same result." Or: "I can make the model get me the result I want." A published record answers both. Anyone can rerun the study against values fixed before the run. As models and prompts change, we expect the engineering results only to improve, and every change shows against the record.

What is inside

Three studies are the examples: rod pump cards, Gulf well permits and a corroded pipeline section. For each, the body shows the data set, the code, the prompt and the values a rerun must match. Appendix A lists each file and version; Appendix B holds this article's own prompt.

In this article: the data set; the code; the prompt; the figure data; the checks.

The data set is named and dated

Every study starts from a data set a reader can download, named with its publisher, its date and its licence.

Some of the observations are as follows:

  • Rod pump: one anonymised field well in our public code library, under the MIT licence, and a public diagnostic plate of ten labelled pump card shapes, a data set published on Mendeley Data in 2020 under CC0 1.0 [5].
  • Well permits: two raw data files of the US Bureau of Safety and Environmental Enforcement (BSEE), the permit file of 2 November 2026 and the borehole file of 12 November 2026, free to download with no account [6].
  • Corroded pipeline: a worked example of 15 wall readings on a 5 by 3 grid, held at one fixed version of our public code library.
  • BSEE lists its files as updated daily, so the file dates fix the published values. The prompt records each file's SHA-256 hash, a fingerprint that changes if the file does.

The code is fixed at one version

The method lives in our public code. Every link points to one fixed version, a pinned commit, so a later change to the code cannot change what the article cites.

Some of the observations are as follows:

  • Rod pump: the pump card is computed from the surface card with the wave equation [4]. Two numerical methods are kept side by side; on the example well their pump cards differ by 0.26 % of the load range.
  • Rod pump: the data links are pinned, and the prompt runs the library's latest analysis code. A script grades each rerun against the published values, so newer code is held to the same result.
  • Well permits: the counting script needs only the Python standard library, and the counting rules are written down: each well is counted once, at its first New Well permit.
  • Corroded pipeline: one script rebuilds the assessment from the pinned inputs, with five published strength methods side by side: B31G, Modified B31G, RSTRENG, RSTRENG-2D and DNV-RP-F101. Package versions can drift, so the prompt asks for the versions used to be recorded.
  • Where a method is simplified, the article says so: the pipeline rating uses a simplified form of the local metal-loss route of API 579-1/ASME FFS-1 [7], and the section is referred to a formal evaluation before the rating is adopted.

The prompt carries the values to match

Our Deckhand assistants ran each analysis. The reusable prompt gives the same work to a reader's own assistant, in plain instructions, with the values the rerun must match (Table 1). It names no model: the values, not the model, decide whether a rerun agrees.

Some of the observations are as follows:

  • None of the three needs a paid account to run. The pipeline study cites paid standards, and its code needs no copy of them.
  • The rod pump prompt is graded by a script, so the rerun is scored, not just described.
  • The pipeline prompt has the rerun rewrite the results file and compare it with the published one; a faithful rerun shows no numerical change. It needs about 10 minutes and 3.5 GB of disk.
  • Each prompt has a second part that adapts it: a reader's own card, another region or depth band, or a reader's own wall readings.

Every figure carries its own data file

The numbers behind each figure are published as a file beside it, so a reader can replot them or check one value without rerunning anything.

Some of the observations are as follows:

  • Rod pump: the two cards of Figure 1 are one CSV file at a fixed version, and each of the ten examples of Figure 2 has its own file.
  • Well permits: every figure and table links a CSV file, including the map windows, the yearly counts and the annual oil price.
  • Corroded pipeline: each of the three figures has its CSV file: life by corrosion rate, strength by method and the wall map.

Each report states its checks and misses

An engineering-quality report gives the reader what is needed to judge it: the checks run, the inputs that matter most and where the method falls short.

Some of the observations are as follows:

  • Rod pump: the shape model names 6 of the 10 reference conditions, and the article lists the four it misses, each read as a traveling valve leak.
  • Rod pump: the inputs that matter most are stated. A 1 % larger rod diameter lowers the maximum pump load by about 3.2 %; a 1 % load-cell gain error raises it by about 2.6 %.
  • Well permits: what is left out is counted, such as the 10 wells whose first New Well permit gives no requested spud date. The oil price is shown beside the counts, and no cause is fitted.
  • Corroded pipeline: the five methods give four different pressures, and the article explains why. The highest allowable pressure is 21.6 % above the lowest.

Published misses matter as much as published values. A rerun steered toward a wanted answer still has to match the same check values and account for the same misses.

Our hypothesis: with the record published, a rerun that disagrees is a finding to trace, not an argument over whose run was right. Models and prompts will change, but the record stays. Each new run is measured against the last, and we expect the engineering results only to improve.

Appendix B Reusable prompts

This prompt lets your team, or your assistant, check a Deckhand study the way this article describes: find its data set, its code and its prompt, rerun it, and compare the values. To have a study of your own engineering question done for you instead, see below.

What you need to run this

  • Data required: none beyond the public data sets the three studies name (Appendix A).
  • Data required to adapt: a published study you want to check, with its data set, code and check values.
  • Paid or behind an account: none to run the three studies. The pipeline study cites paid standards; its code needs no copy of them.
  • Changes over time: the prompts and data links are pinned to commits; the rod pump prompt runs the latest analysis code against fixed check values. BSEE lists its files as updated daily, so the permit counts hold for the file dates given. Record the assistant, the model and the package versions you used, so your own run is traceable too.

Reproduce the published result

Give this prompt to your assistant:

Check the article "Fitness for service of corroded pipelines: strength and remaining useful life (RUL)", revision 5 of 19 Nov 2026. Open its prompt file at https://github.com/vamseeachanta/digitalmodel/blob/40f188ae311127c196216e2aa0206213479228d2/docs/articles/fitness-for-service-corroded-pipelines/reusable-prompts.md and follow "Reproduce the published result" step by step. Give me a table with each check value the file lists, the value you got, and whether they agree to 4 significant figures. Then list the study's data set, the code version and each figure data file, each with its link, and mark any you could not open. Say which assistant and model you used, and the package versions installed.

Check values: reduced rating 1,022 psi [7.046 MPa], 127.7 % of the 800 psi design pressure; remaining strength factor 0.5896 against 0.90; life 23.1, 11.5 and 5.8 years at 0.0025, 0.005 and 0.01 in/year. Allow about 10 minutes and 3.5 GB of disk.

Adapt it to your project

Give the same prompt the title and prompt file of another study. For the rod pump study [1], the prompt file grades the rerun with its own script. For the well permits study [2], the prompt reruns on the latest BSEE files, and the counts change with the file date. For a study of your own team, the checks that still apply are: one named data set with its date; code at one fixed version; a prompt with values to match; and a data file beside every figure.

Public data set: the data sets of the three studies, as listed in Table A1: the rod pump example well and diagnostic plate, the BSEE permit and borehole files of 2 and 12 November 2026, and the corroded-pipeline worked example.
