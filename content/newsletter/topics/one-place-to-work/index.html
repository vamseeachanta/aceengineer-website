One place to work

Summary: We now use AI assistants for many tasks: in a chat window or an app, on a phone, and on personal and work computers. AI assistants use language models that do not always give the same answer. We are running into the familiar territory of "the answer can change from one run to the next, and with the wording of the question."

When we dealt with IT and programmers, many a times, we faced a related frustration: "oh.. but it works on my machine." This answer was so familiar for administrative tasks such as opening a Microsoft word file or crash). Equally, the same experience when we ran a script not able to run let alone getting same result. We now meet a similar problem in everyday AI use: one person gets a result that another cannot repeat.

One of the solutions is to keep each job in one folder, with its files, its tools, its prompts and its record of changes. Let your AI assistant work through this created set environment. The AI assistants we use keep a record of each session. To check a result, or run it again, you need its prompt, its inputs and that record. So the home for this data matters.

The article shows how this grows from one engineer to a team and then to the company. In our experience, it takes a few (> 10-20) reasonably sized sessions to realize these benefits; we have not measured this. Treating AI assistants as loyal team members who need help will get us a long way. Similar to training your employee team, training this single work storage place will make immense difference.

Engineering work often lives in many places: e-mail attachments, personal and shared drives, chat threads, and spreadsheets or scripts on one engineer's laptop. Each copy changes on its own. The risk is a result that goes out from an out-of-date input, and nobody can say which input was used.

AI assistants make this more important. Answers can differ from one run to the next. Keep the prompt, the inputs and the assistant's record in the job folder, with the result. Some AI assistants can now change files, not only read them; this article calls them AI agents. An agent can only work on the files it can read, and it can change those files. So the questions are: where are the files, what may the agent touch, and how do you see what it did?

What "one place" means

One place is one folder for each job. The folder holds the job's files and tools, its prompts and the assistant's records, and its record of changes. You ask your AI assistant from the chat or tool you already use, and it works only in that folder. The result comes back to you, and the change goes into the folder's record.

Three layers keep this under control:

  • Data. The agent reads only the files in the job's scope: the folders it is allowed to see. Other files are not visible to it.
  • Execution. One harness: the same tools, the same instructions and the same guardrails for every job. Guardrails are fixed limits: the agent cannot delete files or overwrite history. It proposes each change for a person to review, and every action goes into a log (an audit trail).
  • Results. The result comes back to the place where you asked, with a record of what changed and why.

At level 1 you set most of this up yourself. Open the AI tool only in the job folder, and review each change before you keep it. At levels 2 and 3, the system's permissions enforce the limits, not the instructions to the AI.

The ladder

  1. One person. You keep each job in one folder, with one set of tools and one instruction file for your AI assistant. The instruction file is a short text note: what the job is, the units, the design code and edition, and how to rerun the calculation. Start on public material, such as a textbook example, while you learn how the assistant behaves. Keep client data out of the AI tool until your firm allows it.
  2. The team. The team shares one place, with one scope for each job. The calculation tools and checklists sit in the shared harness, so each new job starts from the team's best version. When a checklist is corrected, the team keeps one copy. The reviewer sees each proposed change before it is accepted.
  3. The organisation. The same place sits inside the organisation's own chat or workspace, and uses the staff's existing sign-ins. Each project has one scope and one audit trail. The system's permissions enforce the guardrails. Outside partners work in a separate place, with their own scope.

You can start at level 1 on your own. Levels 2 and 3 need the team or the company to agree, and the company's IT and security staff to approve.

For a small company

A small company does not need a large platform for this. Start with the work the team repeats: a calculation package, a quote, a drawing set, a test report. Turn one of these into a small tool, for example a spreadsheet template or a short script that builds the package from one input file. Run it on your own computer, with the software and data you already have. Put the tool, its inputs and its record in one place.

We work this way ourselves. Our engineering code, scripts and AI-agent instructions are in repositories: folders that keep every version. Our agents' changes arrive as pull requests (proposed changes), and they are reviewed before they are merged.

An example (invented for this article)

A small engineering firm does beam and frame checks. The firm and its people are invented for this example.

  • Level 1: one engineer keeps each job in one folder, with her check spreadsheet, a record of changes and an instruction file. She opens her AI assistant only in that folder and reviews each change it proposes.
  • Level 2: the firm's three engineers share one place, with one scope for each job. A second engineer asks the assistant to rerun her check, and reviews the result.
  • Level 3: the firm adds a second team. Each project gets its own scope and audit trail. A partner firm works on one project, in a separate place.

What this does not show

This article gives no measured time saving. Setting up the place takes effort, and habits take time to change. Some files must stay where they are: files under document control, and files in the client's own system. List them in the job folder with their location, and do not move them.

Try it Monday

  1. Choose one current job, and check your firm's rules on copying its files.
  2. Make one folder with four sub-folders: inputs, calculations, results and report.
  3. Copy your own working files for that job into the folder.
  4. From now on, work on this job only from this folder.
  5. List the files that must stay elsewhere, and where they are.
  6. Start a change log: a text file with one line for each new result and its input.
  7. Write an instruction file: the job, the units, the design code and how to rerun it.
  8. Before you open an AI tool on the folder, check that your firm allows it.
